# OMAR Learning Protocol v1

## Purpose
Convert repeated corrections and demonstrated work patterns into reusable operating knowledge.

## Learning loop
After meaningful work or a correction:
1. Detect the lesson.
2. Decide whether it is one-off or reusable.
3. Classify scope: GLOBAL / WORKFLOW / BRAND / PROJECT / CAMPAIGN / TEMPORARY.
4. State the rule in operational language.
5. Check it against existing rules for conflicts.
6. Update the narrowest authoritative source.
7. Preserve source isolation.
8. On the next matching task, load and apply it before generating output.

## Promotion rules
- One-off request: do not promote automatically.
- Explicit "always/from now on": durable unless superseded.
- Repeated correction: promote to reusable rule.
- Stable demonstrated workflow: document as workflow protocol.
- Active market/campaign: store as active context, not global truth.
- Locked asset instruction: brand-level hard rule.

## Failure prevention
When Nelson has to repeat a specification that already exists:
- treat it as a retrieval/execution failure;
- locate why the rule was not loaded;
- repair the loading path or precedence;
- do not merely patch the current output.

## Reanalysis
For workflows with an established quality gate, perform the gate automatically before final output. Do not make Nelson request the same reanalysis repeatedly.
