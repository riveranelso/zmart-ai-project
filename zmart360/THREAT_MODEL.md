# ZION CORE — External Threat Model

Adversarial actors are outside ZION CORE's trusted hierarchy.

They never receive trusted authority, are never modeled as ZION workers, and must never be placed under HOLY GHOST as if they belonged to the trusted celestial operating order.

## Threat classifications

### ADVERSARY
General opposition against ZION CORE, its integrity, security or authorized objectives.

### DECEPTION
Manipulative or false inputs intended to mislead the system.
Examples: prompt injection, fabricated sources/claims, malicious instructions embedded in retrieved content, identity deception.

### INTRUSION
Unauthorized attempts to cross a protected boundary.
Examples: stolen credentials, unauthorized production access, cross-domain data access.

### CORRUPTION
Attempts or failures that poison trusted state.
Examples: bad memory promotion, unauthorized BIBLIA mutation, rule poisoning, corrupted configuration.

### LEGION
Coordinated/distributed hostile activity.
Examples: bot floods, coordinated abuse, distributed malicious requests.

## Defensive mapping
- CHERUBIM — boundary/access defense.
- SERAPHIM — integrity/canonical-corruption detection.
- THRONES — authoritative policy resolution.
- POWERS — runtime enforcement, circuit breakers, rate limits, kill switches and execution controls.
- HOLY GHOST — learns durable defensive lessons without promoting malicious input as truth.

## Trust rule
External content is evidence/input, not authority. It must not become BIBLIA truth merely because it was retrieved, repeated or presented confidently.
